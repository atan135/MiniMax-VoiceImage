# 语音模块升级验收清单（手动测试）

> 配套文档：`summary/语音模块升级_checklist.md` / `summary/语音模块升级_字段映射表.md` / `docs/voice.md`
> 测试环境：本地启动 `npm run dev`（端口 3000）+ `cd client && npm run dev`（端口 5173）
> 前置：`.env` 含 `API_KEY`、`DB_*` 等配置，MySQL 服务可用；前端 `npm run build` 通过。

---

## 一、高优先级四项验收

### 1. `channel` 透传（阶段 2）

**目标**：单声道 / 立体声参数能传到后端并被 MiniMax API 接受。

手动步骤：

1. 启动前端，进入 `语音生成` 页。
2. 在"声道"radio group 切换为 `立体声`。
3. 填入文本 + 选择任意音色，点击"生成语音"。
4. 观察结果：音频可播放、`audioSize > 0`、文件保存到 `output/voice/output_*.mp3`。
5. 切回 `单声道` 重复步骤 3，结果一致。

后端验证：

```bash
# 查看后端日志应有：
# [Voice] 请求参数: {..."channel":2...}
```

API 校验（错误情形）：

```bash
# curl 测试 channel=0
curl -X POST http://localhost:3000/api/voice \
  -H 'Content-Type: application/json' \
  -d '{"text":"hi","voiceId":"male-qn-qingse","channel":0}'
# 期望：500 { error: "channel 必须是 1 或 2" }
```

✅ 通过条件：立体声 / 单声道都能正常生成；非法值（0/3/1.5/"1"）返回 500 + 中文错误。

### 2. `english_normalization` 透传（阶段 3）

**目标**：UI 勾选"英文缩写展开"后，请求 payload 包含 `voice_setting.english_normalization`，MiniMax API 接受。

手动步骤：

1. 前端勾选"英文缩写展开"。
2. 提交一条含英文缩写的文本（如 "USA is in N.A."）。
3. 后端日志查看 `[Voice] 请求参数` 应含 `"englishNormalization":true`。

API 校验：

```bash
# curl 测试 englishNormalization="yes"（非法）
curl -X POST http://localhost:3000/api/voice \
  -H 'Content-Type: application/json' \
  -d '{"text":"hi","voiceId":"v1","englishNormalization":"yes"}'
# 期望：500 { error: "englishNormalization 必须是布尔值" }
```

✅ 通过条件：勾选后能正常生成；非法类型返回中文错误。

### 3. `subtitle_file` 持久化与下载（阶段 4）

**目标**：勾选"生成字幕"后，字幕内容入库，前端展示，并能通过 `GET /api/voice/subtitle/:id` 下载。

手动步骤：

1. 前端勾选"生成字幕"，提交一段文本。
2. 等待生成完成，结果区应出现"字幕"块，含 `<pre>` 内容和"下载字幕"按钮。
3. 点击"下载字幕"，浏览器下载 `.txt` 文件，内容与展示一致。
4. 进入 `历史记录` 页，点击刚生成的记录（type=voice），详情弹窗应有"加载字幕"按钮。
5. 点击"加载字幕"，应显示 `<pre>` 字幕内容。

数据库验证：

```bash
mysql -u root -p minimax \
  -e "SELECT id, type, subtitle IS NOT NULL AS has_subtitle FROM generation_history ORDER BY id DESC LIMIT 5"
# 期望：刚生成的 voice 记录 has_subtitle = 1
```

API 验证：

```bash
# 用上一步查到的 ID
curl -i http://localhost:3000/api/voice/subtitle/<id>
# 期望：Content-Type 为 application/json / text/vtt / text/plain 之一；body 是字幕原文
```

✅ 通过条件：DB 入库、前端展示、下载、详情加载、API 拉取五项全通；不勾选时字幕列应为 NULL。

### 4. `stream` 流式输出（阶段 7）

**目标**：勾选"流式输出"后，前端按 SSE 接收分块音频；后端响应 `Content-Type: text/event-stream`。

手动步骤：

1. 前端勾选"流式输出"，提交一段文本。
2. 观察前端：进度文字"正在接收流式数据... 已接收 N 个音频块"，N 逐渐增长。
3. 接收完毕后进度变为"流式接收完成：共 N 个音频块"，生成 audio URL，可播放。

后端验证：

```bash
curl -i -N -X POST http://localhost:3000/api/voice \
  -H 'Content-Type: application/json' \
  -d '{"text":"hi","voiceId":"v1","stream":true}'
# 期望响应头：
# HTTP/1.1 200 OK
# Content-Type: text/event-stream
# Cache-Control: no-cache
# Connection: keep-alive
# X-Accel-Buffering: no
# body 多行 "data: {...}\n\n"
```

✅ 通过条件：SSE 头正确；至少 1 个 chunk 到达；流式模式下历史**不写库**（`generation_history` 不新增 voice 记录）。

## 二、中优先级四项验收

### 5. `pcm` 格式（阶段 2）

**目标**：`audioFormat` 下拉包含 `pcm` 选项，选中后能正常生成。

手动步骤：

1. 前端"音频格式"下拉选择 `pcm`。
2. 提交生成，文件保存为 `output/voice/output_*.pcm`（`audio/mpeg` 的 blob URL 仍可播放，因浏览器可解码 PCM）。

API 校验：

```bash
curl http://localhost:3000/api/voice/options | jq .data.audioFormatList
# 期望：["mp3","wav","flac","pcm"]
```

✅ 通过条件：下拉含 pcm；生成成功；文件扩展名为 .pcm。

### 6. `voice_modify` 音色调整（阶段 8）

**目标**：折叠区展开后，调整 5 个数值滑杆 + 音效多选，能传到后端。

手动步骤：

1. 前端展开"高级参数"折叠区。
2. 拖动"音高减" slider 到 -50；"音高增" slider 到 30；勾选 1-2 个音效。
3. 提交生成，音频应播放正常。

后端验证：

```bash
# 查看后端日志应有：
# [Voice] 请求参数: {..."voiceModify":{...pitch_decrement:-50,pitch_increment:30,...sound_effects:["spacious_echo"]}...}
```

前端默认验证（不打开折叠区）：

```bash
# 提交不带 voiceModify 的请求
curl -X POST http://localhost:3000/api/voice \
  -H 'Content-Type: application/json' \
  -d '{"text":"hi","voiceId":"v1"}'
# 后端日志：voiceModify 不应出现在 maskedBody 中（前端按 isVmDefault 跳过挂载）
```

✅ 通过条件：5 个滑杆任一非默认值时 payload 含 voiceModify；音效多选传递为数组；默认状态完全跳过字段。

### 7. `pronunciation_dict` 发音字典（阶段 8）

**目标**：tone / phoneme 两种模式都能正确发送。

手动步骤（tone 模式）：
1. 折叠区选"整体 tone 字符串"，填入 `hello/(həˈloʊ)/`。
2. 提交生成；后端日志中 `pronunciationDict` 应为字符串 `"hello/(həˈloʊ)/"`。

手动步骤（phoneme 模式）：
1. 折叠区选"音素级别对象"，填入 `{"苹果":"p ing guo"}`。
2. 提交生成；后端日志中 `pronunciationDict` 应为对象 `{"苹果":"p ing guo"}`（JSON.parse 后）。

手动步骤（非法 JSON）：
1. phoneme 模式填入 `{invalid json`。
2. 提交生成，前端应弹出 `ElMessage.error('发音字典 JSON 格式错误')`，请求**不发送**。

手动步骤（空输入）：
1. 折叠区不填内容。
2. 提交生成；后端日志 `pronunciationDict` 应**不在** maskedBody 中（前端按 undefined 跳过）。

✅ 通过条件：四种情形（前三种含值 + 最后一种空）行为均符合预期。

### 8. `timbre_weights` 多音色权重（阶段 8）

**目标**：列表增删改能正确发送，过滤空 voice_id。

手动步骤：
1. 折叠区点"添加音色权重"，输入 `voice_id="male-qn-qingse"`，`weight=70`，再添加一条留空 voice_id。
2. 提交生成；后端日志中 `timbreWeights` 应**只有 1 条**（空 voice_id 被过滤）。

手动步骤（多条）：
1. 添加 2-3 条完整记录。
2. 提交生成；后端日志中 `timbreWeights` 应包含全部 2-3 条。

手动步骤（全空）：
1. 不添加任何记录。
2. 提交生成；后端日志 `timbreWeights` 应**不在** maskedBody 中。

✅ 通过条件：过滤规则正确；非空数组透传；空数组跳过。

### 9. `model` 模型选择（阶段 5）

**目标**：`/options` 返回 `modelList`，UI 下拉能切换并传递。

手动步骤：
1. 前端"模型"下拉应包含 5 个官方模型。
2. 切换为 `speech-02` 提交生成；后端日志 `model:"speech-02"`。
3. 切换为 `speech-2.6-hd` 重复步骤 2。

API 验证：

```bash
curl http://localhost:3000/api/voice/options | jq .data.modelList
# 期望：["speech-2.6","speech-2.6-hd","speech-02","speech-02-hd","speech-2.8-hd"]
```

✅ 通过条件：下拉含 5 模型；切换后 payload 含对应 `model` 字段。

## 四、已知限制（不在本验收范围）

- 字幕内容展示性能：`<pre>` 直接渲染整段字幕，长视频字幕（>1MB）下可能性能下降。本阶段未做懒加载或分页。
- JSON 字幕未格式化：`subtitle_file` 是 JSON 时按原始压缩字符串展示。
- 流式历史不入库：`stream=true` 不写 `generation_history`，与 `stream=false` 行为不同；当前实现优先保证流式响应速度。
- 下载文件扩展名固定 `.txt`：未根据 contentType 区分 `.json` / `.vtt`。
- 音效 12 项枚举与 MiniMax 官方枚举保持一致；若官方后续增删，需同步 `SOUND_EFFECTS_LIST`。
